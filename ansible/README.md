# Ansible для SOC-лаборатории

[Главная страница](../README.md) · [Сервис управления секретами](../docs/03-secret-service-and-ansible.md)

Я использовал Ansible через WSL для управления четырьмя VM. Пароли получал из собственного сервиса секретов через lookup-плагин. Для Linux применял SSH, для Windows — WinRM по HTTP/5985. Учётная запись управления — `ansible`.

В этом каталоге я собрал inventory, общие параметры подключения и интеграцию с сервисом секретов.

## Файлы каталога

| Файл / каталог                                                                   | Для чего я его использую                                          |
| -------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| [inventory/hosts.yml](inventory/hosts.yml)                                       | Адреса узлов и состав групп                                       |
| [inventory/group_vars/all.yml](inventory/group_vars/all.yml)                     | Общие параметры, выбор SSH/WinRM и API секретов                   |
| [inventory/host_vars/app-secrets.yml](inventory/host_vars/app-secrets.yml)       | SSH-подключение к приложению и путь пароля                        |
| [inventory/host_vars/soar-ir.yml](inventory/host_vars/soar-ir.yml)               | SSH-подключение к SOAR и путь пароля                              |
| [inventory/host_vars/soc-wazuh.yml](inventory/host_vars/soc-wazuh.yml)           | Путь пароля и параметры центрального узла                         |
| [inventory/host_vars/win10-endpoint.yml](inventory/host_vars/win10-endpoint.yml) | Учётная запись Ansible, путь пароля, адреса Firewall и приложения |
| [lookup_plugins/secret_service.py](lookup_plugins/secret_service.py)             | Получение значения секрета через API                              |
| [create_ansible_secret.py](create_ansible_secret.py)                             | Создание/обновление секретов, выдача чтения и проверка доступа    |
| [ansible.cfg](ansible.cfg)                                                       | Пути inventory, ролей, плагина и временного каталога              |
| [requirements.yml](requirements.yml)                                             | Коллекции и готовые роли                                          |

Готовые роли устанавливаю в `roles/` из зависимостей. В этом каталоге публикую конфигурацию доступа и Python-скрипты; отдельные playbook усиления сюда не включены.

## Inventory

| Группа             | Узлы                                                                        |
| ------------------ | --------------------------------------------------------------------------- |
| `wazuh_servers`    | `soc-wazuh` — `192.168.31.227`                                              |
| `ubuntu_servers`   | `soc-wazuh`, `soar-ir` — `192.168.31.209`, `app-secrets` — `192.168.31.210` |
| `docker_hosts`     | `soar-ir`, `app-secrets`                                                    |
| `windows_endpoint` | `win10-endpoint` — `192.168.31.236`                                         |

Один узел я включаю в несколько групп по назначению: например, `app-secrets` одновременно относится к Ubuntu и Docker-хостам.

## Общая конфигурация

В `inventory/group_vars/all.yml` я объединил общие параметры лаборатории, подключения и API сервиса секретов. Для группы `windows_endpoint` выбираю WinRM по HTTP/5985 с NTLM, для остальных узлов — SSH на порту 22. Учётная запись управления — `ansible`; пароли получаю через плагин по путям из `host_vars`. Повышение прав по умолчанию отключено.

## Получение секретов

| Узел             | Путь                                          |
| ---------------- | --------------------------------------------- |
| `app-secrets`    | `ansible/hosts/app-secrets/ssh/password`      |
| `soc-wazuh`      | `ansible/hosts/soc-wazuh/ssh/password`        |
| `soar-ir`        | `ansible/hosts/soar-ir/ssh/password`          |
| `win10-endpoint` | `ansible/hosts/win10-endpoint/winrm/password` |

Плагин обращается к `https://192.168.31.210:8443`, передаёт ключ в `X-API-Key` и ожидает значение в ответе API. Тайм-аут запроса — 15 секунд. Пароль возвращается Ansible и не записывается в inventory.

Для URL плагин сначала учитывает аргумент вызова и переменную Ansible, затем окружение и `.env`. Для API-ключа использует аргумент вызова, окружение или `.env`. 

## Скрипт подготовки секретов

Через `create_ansible_secret.py` я выполняю следующий процесс:

1. Задаю адрес приложения и параметры TLS.
2. Выбираю создание сервисной учётной записи или существующий ключ и `principal_id`.
3. Ввожу административные данные для обращения к API.
4. Выбираю четыре пути лаборатории и задаю значения.
5. Создаю секреты либо новые версии существующих.
6. Выдаю сервисной учётной записи право `read`.
7. Записываю `.env` и проверяю чтение через сервисный ключ.

Скрипт предлагает также пути `win-server` и `ndr-sensor`. При подготовке своей лаборатории я пропускаю их. Пароль администратора и существующий ключ вводятся скрыто; значения создаваемых секретов скрипт запрашивает с отображением в консоли. При итоговой проверке чтения выводит метаданные без значений секретов.

Для `.env` скрипт устанавливает права `0600`; перед перезаписью существующего файла запрашивает подтверждение. Сам `.env` я исключаю из Git.

## Состав опубликованных материалов

В лаборатории я использовал одну LAN — `192.168.31.0/24`. Адреса четырёх узлов зафиксировал в `inventory/hosts.yml`.

CIS L1 я применил к основе приложения/SOAR, Windows усилил мягко, а Wazuh оставил без CIS L1. Роль Windows Server 2022 присутствует в зависимостях, но такой VM в итоговой лаборатории нет.

В каталоге я сохранил inventory, параметры подключения и Python-скрипты интеграции с сервисом секретов. Отдельные playbook усиления ОС в этот комплект не включал.
