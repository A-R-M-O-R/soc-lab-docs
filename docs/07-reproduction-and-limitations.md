# 7. Воспроизведение и ограничения

[Главная страница](../README.md)

## Что я публикую

В этом репозитории я собрал архитектуру, настройки управления, описание защиты, условия правил обнаружения, разбор сценариев атак и скриншоты. Приложение разместил отдельно: [Secret-manage-service](https://github.com/A-R-M-O-R/Secret-manage-service).

XML правил Wazuh и JSON-экспорт Shuffle в опубликованный комплект не включены.

Для чтения отчёта достаточно этих файлов: все иллюстрации лежат рядом с документацией и открываются по относительным ссылкам.

В `ansible/` я включил inventory, переменные, конфигурацию, список зависимостей, lookup-плагин и скрипт подготовки секретов. Playbook усиления ОС и полный переносимый комплект SOAR в этот репозиторий не включал.

## Проверка результата

| Сценарий               | Что я проверяю                                                                   |
| ---------------------- | -------------------------------------------------------------------------------- |
| Локальный вход Windows | 100301, правильный пользователь и узел, Alert в TheHive                          |
| SSH                    | 5758, observables, задание DShield и связанный комментарий                       |
| Подбор пароля API      | 100401 и созданный Alert; доступность комментариев зависит от лицензии установки |
| Перебор путей секретов | 100411 и созданный Alert; доступность комментариев зависит от лицензии установки |

Для сопоставления результатов я использую время теста, событие Wazuh, исполнение Shuffle и Alert. В этом отчёте сохранил доступные скриншоты; полного экспорта каждого исторического исполнения нет.

## Ограничения

- Автоматическое сдерживание атак я не включал в итоговый объём.
- После истечения лицензии TheHive в моей установке добавление комментариев к последним API Alerts стало недоступно.
- Ключ Shodan истёк; остальные шесть анализаторов работают.
- Отдельные журналы аудита приложения, PostgreSQL и прикладные журналы SOAR я не собираю в Wazuh.
- Правило повторных 403/404 проверяет ошибки сервиса и не ограничено только авторизованным перебором путей.

При переносе Shuffle нужно проверить ссылки на результаты действий, параметры API и реквизиты новой установки. В опубликованной PNG-схеме я сохранил переходы из JSON; сами реквизиты в отчёт не включал.

На Linux и в плагине использовал лабораторные исключения, включая настройки доверия SSH/TLS. Wazuh оставил без CIS L1 с SCA 39%, Windows усилил мягко. Сегментацию VLAN и отказоустойчивость не внедрял.

## Резервирование

Я использовал локальные снимки VM. Отдельное восстановление PostgreSQL и SOAR с проверкой данных не выполнял. Для переноса данных на новую установку этот этап требует самостоятельной подготовки.

## Практическая работа

Я сосредоточился на практике ИБ и SOC: развёртывании среды, применении настроек, проверке источников событий, тестировании атак и разборе интеграционных проблем. Для приложения и автоматизации использовал готовый код и роли; самостоятельное авторство их исходного кода не заявляю.
